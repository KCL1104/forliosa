# 報價更新頻率與條款調查：現有來源能不能「每分鐘更新一次價格」

> 撰寫：2026-11-13（研究子代理）。問題來自產品負責人：「調查我目前使用的報價 API 的條款，是否允許至少每分鐘更新一次價格。」
>
> **這不是法律意見。** 要簽約或對外收費前，請以交易所、資料商的書面回覆為準。
>
> **標示**
> - 【直接讀到】這次（2026-11-13）自己打開原始頁面、PDF、API 說明檔或本 repo 程式碼讀到的。
> - 【次級來源】只有搜尋摘要、第三方說法，或前一份研究（`data-sources-licensing.md`，2026-11-12）的搜尋摘要，這次沒能打開原文。
> - 【推論】研究者自己的判斷。
>
> **這次查得到與查不到的**
> - 打得開：`www.twse.com.tw`（使用條款、即時／延遲交易資訊頁、問答集、收費標準 PDF、管理辦法 PDF、使用交易資訊契約 PDF）、`openapi.twse.com.tw`、`www.tpex.org.tw`（使用條款、資訊購買頁、OpenAPI 說明檔）、`openapi.taifex.com.tw`（說明檔）、`finmind.github.io`、GitHub（Shioaji 文件原始碼、政府資料開放授權條款全文）。
> - 打不開（這個環境的網路白名單沒有）：`developer.fugle.tw`、`sinotrade.github.io`（改讀它在 GitHub 的原始碼）、`www.taifex.com.tw`、`data.gov.tw`、`www.tradingview.com`；富邦、Yahoo 的條款頁沒有嘗試直接開，只做了搜尋。這些只能標【次級來源】。
> - 證交所與 FinMind 的網頁是用「把網頁轉成文字再回答問題」的工具讀的，引文是工具回傳的原句；證交所的三份 PDF、櫃買的條款與資訊購買頁、三個 API 說明檔、Shioaji 文件原始碼、授權條款全文是下載後自己讀的。
> - **沒有**呼叫證交所 MIS，也沒有呼叫證交所網站的資料端點。對開放資料 API 只做了：三個說明檔（swagger）各一次，另外在盤中（11:59）對四個資料端點各發一次請求、只取檔頭與前 1.5 KB，用來確認「盤中時段資料有沒有變」。

## 1. 一頁結論

**直接回答：只有一半可以。條款沒有禁止「每分鐘查一次」，但用現在的來源做不到「每分鐘更新價格」。**

1. **現在用到的報價全部是收盤後資料，一天只變一次。** 證交所 OpenAPI、櫃買 OpenAPI、shioaji-data 都只有「最新一個交易日的收盤」。2026-11-13（週五）11:59 盤中實測，四個端點回的都還是 11/12 的資料【直接讀到】。每分鐘去問一次，拿到的是同一個收盤價。
2. **查詢頻率本身沒有被條款限制。** 兩個 OpenAPI 的說明都寫「歡迎各位介接使用」，沒有公布呼叫次數上限；資料依《政府資料開放授權條款》可以顯示給其他使用者，條件是標示來源【直接讀到；櫃買各資料集的授權標示是次級來源】。所以答案是「可以每分鐘查，但沒有意義」。
3. **有盤中價格的來源，目前都沒有在用，而且都不能拿來顯示給別人。** 證交所網站使用條款禁止未經同意用程式下載【直接讀到】，MIS 是證交所的網站，沒有找到它另有條款【推論：適用同一份】；券商 API 的行情只給開戶本人【直接讀到辦法；各券商同意書未讀到】；FinMind 的即時資料所有方案都不能「直接呈現於 web、App 等對外介面」【直接讀到】。
4. **「每分鐘更新」在交易所的規則裡不是一個比較便宜的類別。** 證交所辦法只分三種：盤中傳送、延遲不到 20 分鐘的都是「即時資訊」；延遲 20 分鐘以上是「延遲資訊」；收盤後是「盤後資訊」。而且收費標準寫明：用程式定時更新的畫面，一律算「自動更新」【直接讀到】。
5. **要合法做到盤中每分鐘更新，只有三條路**（第 4 節）：
   - 付費取得**延遲報價**授權：證交所 NT$180,000／半年（約 NT$30,000／月），另加櫃買與資料廠商的費用（這次沒查到金額）。使用者看到的是 20 分鐘前的價格，可以每分鐘自動更新。
   - 付費取得**即時報價**授權：證交所資訊費 NT$100,000／月起（5,000 戶以內、自動更新），很可能還要加每月 NT$60,000 的傳輸授權費【推論】，另加櫃買與廠商費用。
   - **每位使用者用自己的券商或資料商帳號**，報價只回到他本人的畫面。Forliosa 不必付授權費，但要先取得券商或資料商的書面確認，而且只有設定過的人看得到。
6. **免費而且條款明文允許的盤中報價來源：這次沒有找到。** 唯一零成本、沒有條款疑慮的做法是「放一個連結，讓使用者自己到證交所基本市況報導看」。

### 2.2 沒有在用的

- **證交所 MIS**：2026-11-12 已移除，原本背景程式每 60 秒輪詢一次的工作也一併刪除；舊資料列（來源 `twse-mis`、`twse-web`）在任何模式都不讀。
- **Yahoo Finance 報價**：程式裡沒有任何 Yahoo 報價端點。白名單裡唯一的 Yahoo 網址是 `tw.stock.yahoo.com/rss`（新聞標題，只在 personal）。`datapolicy.py` 裡的 `yahoo` 只是一個「非商用」標籤，沒有對應的資料提供者。
- **券商 API（Shioaji、富果、富邦）**：程式裡沒有。`shioaji_data` 是 GitHub 上的資料檔，不是券商 API。
- **美股報價**：commercial 模式沒有來源（查詢回 404）；personal 模式是示範資料。

### 2.3 畫面現在怎麼更新

- 前端的個股總覽、自選清單本來就每 60 秒向 Forliosa 自己的伺服器重抓一次；另有一個推送報價的端點 `/stream/quotes`，預設每 5 秒送一次。
- 伺服器端報價快取 30 秒；對交易所 OpenAPI 的直接查詢 10 分鐘內最多一次；對 `twse.com.tw` 主機兩次請求至少間隔 3 秒、`tpex.org.tw` 至少 2 秒。
- 所以**畫面已經是每分鐘更新，只是後面的資料一天只變一次**。`/instruments/{symbol}/intraday`（分時走勢）在任何模式都回空的。

## 3. 各來源的條款與更新頻率

### 3.1 證交所 OpenAPI

- **說明檔原文**（<https://openapi.twse.com.tw/v1/swagger.json>，2026-11-13）【直接讀到】：
  > 「本平臺提供臺灣證券交易所服務API，歡迎各位介接使用。」並附兩個連結：使用條款（`www.twse.com.tw/zh/page/terms/use.html`）、授權說明網址（`data.gov.tw/license`）。
- **有哪些價格資料**：143 個端點。和價格有關的只有每日或更慢的：`STOCK_DAY_ALL`（上市個股日成交資訊）、`FMSRFK_ALL`（月）、`FMNPTK_ALL`（年）、`MI_INDEX`（每日收盤行情－大盤統計）、`TWT53U`（盤後零股）等。**沒有任何個股盤中報價端點**【直接讀到】。
- **`MI_5MINS`「每 5 秒委託成交統計」不是盤中資料**：它是全市場的累計委託與成交統計（不是個股價格），而且是整天結束後才放上來的一整日序列（盤中看到的檔案約 65 萬位元組、從 09:00:00 開始、檔案時間是開盤前）【直接讀到，見下表】。在政府資料開放平臺上，它的分類名稱是「盤後資訊 > 每5秒委託成交統計」【次級來源：搜尋結果的資料集標題】。
- **盤中實測**（2026-11-13 週五 11:59，台北時間；依行事曆是交易日，沒有另外向交易所確認當天有開盤）【直接讀到】：

  | 端點 | 回應裡的資料日期 | 檔案最後修改時間（換算台北時間） |
  |---|---|---|
  | 證交所 `STOCK_DAY_ALL` | 1151112（11/12） | 11/13 05:20:45 |
  | 證交所 `MI_5MINS` | 沒有日期欄位；內容是從 09:00:00 起的整日序列 | 11/13 05:22:41 |
  | 櫃買 `tpex_mainboard_quotes` | 1151112（11/12） | 11/12 23:30:06 |
  | 櫃買 `tpex_active_advanced`（名稱是「上櫃盤中個股漲幅排行」） | 20261112（11/12） | 11/12 23:30:19 |

- **收盤後多久更新**：官方沒有文件。本 repo 的紀錄是 11/12 晚上 22:15 證交所 `STOCK_DAY_ALL` 還是 11/11 的收盤（櫃買當時已是 11/12）（`CONTRACT_NOTES.md`）；這次看到檔案時間是隔天 05:20。【推論】上市的收盤價經由 OpenAPI 拿到的時間，可能是當天深夜到隔天清晨，而不是收盤後幾分鐘。只有一天的觀察，要多看幾天才能確定。
- **使用規則與頻率**：說明檔與使用條款都**沒有**寫呼叫次數或頻率上限【直接讀到】。回應沒有限流相關的檔頭；檔案經由 CDN 快取提供（`Server: HiNetCDN`、`X-Cache: HIT`），並帶有 `ETag` 與 `Last-Modified`，可以用很小的請求確認「檔案有沒有換新」【直接讀到】。第三方專案有人自行設定每次間隔 0.5 秒「避免被視為 DDoS 攻擊」，那是他們自訂的數字，不是證交所公告【次級來源】。本 repo 的紀錄是這台主機偶爾會中斷連線。
- **服務可以隨時變更**：使用條款第 5 條「服務變更及通知」，證交所可不經通知修改或停止服務【直接讀到條文標題；內容為摘要】。

## 4. 合法取得「每分鐘更新」或延遲報價的路線與費用

### 4.1 先講規則：盤中資料只有「即時」和「延遲」兩種

- 延遲不到 20 分鐘 → 即時資訊；20 分鐘以上 → 延遲資訊（辦法第 3 條）【直接讀到】。
- 收費標準對「自動更新」的定義【直接讀到】：
  > 「『非自動更新』係指資訊傳輸終端接訊設備之報價畫面需手動更新資訊者；以程式設定時間換頁查詢者，將視為畫面具自動更新功能。」
- 【推論】所以「每分鐘自動更新、價格是最新的」＝即時資訊＋自動更新，是最貴的那一級；「每分鐘自動更新、但價格是 20 分鐘前的」＝延遲資訊。

| **FinMind Sponsor**（NT$999／月） | 見 3.7。FinMind 自己建議「讓使用者在你的產品輸入自己的 FinMind 帳號」【直接讀到】 | 要問（自架網頁算不算「對外介面」沒寫清楚） | 用產品負責人的帳號：不行。每人自己的帳號：FinMind 有提到這個做法，細節要問 |

【推論】這條路 Forliosa 不必付授權費，但代價是：每個想看盤中價格的人都要有自己的券商帳戶或付費帳號，並完成 API 申請；沒設定的人仍然只看到收盤價；技術上最安全的做法是讓資料直接從使用者自己的裝置連到券商，不經過 Forliosa 的伺服器。上線前要有券商或資料商的書面回覆。

### 4.5 商業資料商

- 台灣的行情廠商（要顯示延遲或即時資料，一定會經過其中一家）：名單這次讀不到，價格由各家自訂【直接讀到問答集大意】，都要詢價。富果的行情由時報資訊與富果共同提供【次級來源：前一份研究】，可以問它有沒有給第三方產品顯示用的企業方案。
- 國外資料商：搜尋摘要說 Twelve Data 對美國以外的價格資料做商業使用要先經核准，再散布要另簽合約；EODHD 是商業使用請直接聯絡【次級來源：搜尋摘要，原頁沒有打開】。兩家都沒有查到「可以把台股延遲報價顯示給終端使用者」的公開條款或價格。交易所自己的授權是另一回事，不會因為向國外廠商買就免除【推論】。
- TradingView 的嵌入元件：它的常見問題說元件免費、帶 TradingView 標誌；交易所要求每個網站各自付即時資料費，所以元件裡的交易所資料只能是延遲的【次級來源：搜尋摘要；網站打不開】。台股在元件裡能不能顯示、延遲多久，這次沒有確認。這種做法是「TradingView 在它的框裡顯示」，Forliosa 拿不到數字，不能用來算損益。

### 4.6 免費而且明文允許的

- **盤中報價的免費 API：沒有找到。** 證交所、櫃買的開放資料只有盤後；MIS 免費的是「瀏覽」。
- **零成本而且沒有條款疑慮的做法只有連結**：在個股頁放「到證交所基本市況報導看即時報價」的連結，使用者自己點過去看。【推論】讀到的條款沒有禁止別人連結到它的網頁；Forliosa 沒有下載、也沒有轉載任何資料。

## 5. 建議

依成本由低到高。金額只有證交所的部分是直接讀到的；櫃買與廠商的費用未知，所以 C、D 的總額現在算不出來。

| 方案 | Forliosa 的成本 | 使用者看到什麼 | 把握程度 |
|---|---|---|---|
| **A. 維持收盤價**（現況） | NT$0 | 最新一個交易日的收盤價；盤中不變 | 高：完全在開放資料授權內 |
| **A＋. 維持收盤價，加三個不花錢的改善** | NT$0，少量工程 | ①價格旁清楚寫「收盤價・日期」，盤中不讓人誤以為是現價；②個股頁加「看即時報價」連結到證交所／櫃買自己的頁面；③收盤後用很小的請求（檢查檔案有沒有換新）盡早抓到當天收盤，而不是固定時間抓 | ①②高；③中：條款沒有禁止，但證交所什麼時候更新只觀察了一天 |
| **B. 每人用自己的帳號看盤中價格** | 授權費 NT$0；工程量大；要先拿到書面確認 | 有設定的人：自己畫面上的即時或接近即時價格；沒設定的人：收盤價 | 中偏低：辦法的文字支持「本人使用」，但各券商同意書沒讀到，伺服器代轉可能不被允許 |
| **C. 延遲報價授權** | 證交所 NT$180,000／半年（預付）＋櫃買（未知）＋廠商供應費（未知） | 全部使用者看到延遲 20 分鐘以上的價格，可每分鐘自動更新；畫面要標「延遲 20 分鐘」與資料來源 | 中：證交所金額與契約確定，其餘要詢價 |
| **D. 即時報價授權** | 證交所資訊費 NT$100,000／月起，很可能再加 NT$60,000／月傳輸授權費＋櫃買＋廠商 | 全部使用者看到即時價格 | 中：同上 |

研究者的看法（不是定論）：

- **現在：A＋。** 這和「初期不付費」「不做即時盤中報價」兩個既有決定一致，而且每分鐘更新價格在零成本下確實做不到。
- **最便宜的合法下一步是寄信，不是寫程式。** 三封信都是零成本：①問證交所：小型服務顯示延遲報價，除了半年 18 萬還有哪些費用，收費標準第 7 項（每帳戶每月 12 元）小型服務能不能適用、有沒有最低金額；②問櫃買：延遲與即時的計費標準；③問一家券商（例如永豐）：每位使用者用自己的 API 金鑰、行情只回到本人畫面，可不可以，伺服器代轉算不算轉接。有了回覆才知道 B、C 實際要多少錢。
- **如果只是產品負責人自己想在盤中看到價格**：B 的「本人帳號、本人畫面」是把握最高的做法，但那是 personal 模式的個人功能，不能開給其他使用者，也不能算進 commercial 模式的產品功能。
- **C 是「讓所有使用者看到盤中會動的價格」最便宜的正式路線**，但證交所一家每月就約 3 萬，還沒算櫃買與廠商；在有收入之前不建議。

## 6. 還沒查清楚的事

1. **櫃買中心的延遲、即時資訊收費標準**：頁面沒有可開的連結，搜尋不到。
2. **廠商端的費用與名單**：證交所簽約廠商名單頁讀不到；各家延遲資料供應費沒有公開價目。
3. **即時資訊的傳輸授權費（NT$60,000／月）是否每一家經由廠商間接連線的網站都要繳**；收費標準第 7 項（按帳戶計費）對小型服務是否適用、有無最低金額。
4. **各券商 API 同意書原文**（永豐、富邦、富果）都沒讀到；「使用者自帶金鑰、伺服器代轉」是否算轉接，沒有任何一家的明文答案。富果的網站這次打不開、富邦的條款這次沒有搜尋到，兩家的數字都沿用前一份研究的搜尋摘要。
5. **FinMind**：自架、只有本人登入的網頁算不算「對外介面」；使用者自帶帳號時，產品本身需不需要 Sponsor Pro。
6. **證交所 OpenAPI 收盤資料的實際更新時間**：只有 11/12 晚上到 11/13 清晨這一次觀察；`Last-Modified` 也可能只是檔案重新產生的時間，而且回應來自 CDN 快取。建議連續記錄幾天。
7. **OpenAPI 有沒有未公布的流量限制**：沒有官方文件；這次與平常的低頻使用都沒有被擋。
8. **期交所網站使用條款原文、Yahoo 條款原文、TradingView 元件條款與台股資料等級**：網站打不開，只有搜尋摘要。
9. **MIS 自己有沒有獨立的使用條款頁**：沒有找到；依規定也沒有去打開 MIS 網站確認。
10. **2026-11-13 是否正常開盤**：依行事曆是交易日，沒有另外查證。若當天休市，3.1 的盤中實測就只能說明「非交易時段資料不變」。
